# 场景 2：TC — 流量整形、P2P 限制与视频优先级

## 1. 应用场景

TC（Traffic Control）是 Linux 的流量控制子系统。eBPF 分类器（`BPF_PROG_TYPE_SCHED_CLS`）可以挂在 `clsact` qdisc 的 ingress/egress 钩子上，用于：

- 网络 QoS：按端口、DSCP、mark 把流量分到不同队列/band；
- 流量整形：与 `htb`、`tbf`、`prio`、`fq_codel` 等 qdisc 配合；
- 包标记与重定向：写 `skb->mark`、`tc_classid`，或 `bpf_redirect`；
- 入向过滤：在 tc ingress 丢弃/限速。

与 XDP 的差别：

| | XDP | TC |
|---|---|---|
| 位置 | 驱动 receive path | 协议栈 qdisc 层 |
| 是否已有 skb | 否（native） | 是 |
| 能力 | 丢弃、改写、重定向 | 丢弃、mark/classid、重定向、与 qdisc 深度集成 |
| 方向 | 主要 ingress | ingress + egress |
| 典型用途 | DDoS 前端 | QoS、整形、策略路由 |

本案例覆盖“为视频流分配高优先级队列，限制 P2P 带宽”的简化版：**按目的端口丢弃 P2P，按目的端口给视频流打 mark，由 `prio` qdisc 的 `fw` 规则选择高优先级 band**。

## 2. 本案例的策略

`tc_qos` 解析 Ethernet（含 VLAN）+ IPv4 + TCP/UDP：

1. 目的端口在 `drop_ports` 中 → `TC_ACT_SHOT`，统计 `dropped_p2p`；
2. 目的端口在 `video_ports` 中 → `ctx.set_mark(video_mark)`，统计 `prioritized`；
3. 其他 → `TC_ACT_OK`，统计 `passed`；
4. 非 IPv4、非首片段、解析失败 → 放行，避免误伤；
5. 丢包事件按 `event_sample` 采样写入 ring buffer。

### 2.1 为什么写 `skb->mark` 而不是 `skb->priority`

`skb->priority` 是 qdisc 选择 band/class 的直接依据，但 aya 0.16 的 `TcContext` 没有暴露可写的 `priority` 字段（`__sk_buff` 的某些字段在不同程序类型下有写限制）。`skb->mark` 是 TC 程序可写的，且标准 `fw` classifier 可以按 mark 分类：

```bash
tc qdisc replace dev eth0 root handle 1: prio bands 3
tc filter replace dev eth0 parent 1: protocol ip handle 0x10 fw flowid 1:1
```

- `handle 0x10` 必须等于 `--video-mark`（默认 16）；
- `flowid 1:1` 是 `prio` qdisc 的最高优先级 band（band 0 对应 `1:1`，数字越小优先级越高）；
- 这样视频流的包会进入高优先级 band，其他流量进入默认 band。

> 这条链路依赖 qdisc 配置。只 attach TC 程序而不配置 qdisc，mark 不会自动产生队列效果。

### 2.2 数据结构

```rust
struct TcConfig {
    drop_ports: [u16; 8],
    video_ports: [u16; 8],
    drop_port_count: u32,
    video_port_count: u32,
    video_mark: u32,
    event_sample: u32,
}

struct TcStats {
    passed: u64,
    dropped_p2p: u64,
    prioritized: u64,
    passed_bytes: u64,
    dropped_bytes: u64,
}
```

### 2.3 方向

| 方向 | 用途 | 本案例 |
|---|---|---|
| `ingress` | 入向过滤/限速，标记供后续策略使用 | 可以丢 P2P；mark 不直接影响本地发送队列 |
| `egress` | 出向 QoS、整形、优先级 | 推荐；mark 可被根 qdisc 的 `fw` 规则消费 |

CLI 默认 `egress`。

## 3. 实验：lo 上的端口丢包

最简单的方式是用 loopback 和 `nc`：

```bash
# 终端 A：启动一个监听 6881 的服务（P2P 端口）
nc -l 127.0.0.1 6881

# 终端 B：附加 TC egress
sudo -E ./target/release/aya-app tc \
    --iface lo --direction egress \
    --drop-port 6881 --drop-port 6882 \
    --video-port 1935 --video-mark 16

# 终端 C：连接 6881
nc 127.0.0.1 6881
```

预期：`nc` 连接卡住/失败；aya-app 打印：

```text
[tc-drop] t=... 127.0.0.1:54321 -> 127.0.0.1:6881 len=60
```

`tc` 统计中 `dropped_p2p` 增长，`prioritized` 对 1935 端口增长。

> 在 loopback 上，`egress` clsact 是否被调用取决于内核路径；如果看不到丢包，请改用 veth 或真实网卡。veth 实验与 XDP 场景相同，只需把 `--iface` 换成 `veth-host`。

## 4. 配置 QoS 并验证优先级

### 4.1 安装 prio qdisc

```bash
sudo tc qdisc replace dev lo root handle 1: prio bands 3
sudo tc qdisc show dev lo
```

输出应包含 `qdisc prio 1: root ... bands 3`。

### 4.2 把 mark 映射到 band

```bash
sudo tc filter replace dev lo parent 1: protocol ip handle 0x10 fw flowid 1:1
sudo tc filter show dev lo parent 1:
```

`handle 0x10` 与 `--video-mark 16` 对应。`fw` classifier 按 `skb->mark` 匹配。

### 4.3 制造视频流量

```bash
# 监听 1935（RTMP 常用端口）
nc -l 127.0.0.1 1935

# 连接
nc 127.0.0.1 1935
```

此时 1935 的包被设置 mark=16，进入 `1:1` band。可以用 `tc -s qdisc show dev lo` 观察各 band 的包/字节计数：

```text
qdisc prio 1: root refcnt 2 bands 3 priomap ...
 Sent 1234 bytes 10 pkt (dropped 0, overlimits 0 requeues 0)
 band 0: Sent ...          # 高优先级（视频 mark）
 band 1: Sent ...
 band 2: Sent ...
```

> `prio` 只是按 band 排队，不是带宽保证。要“保证视频带宽/限制 P2P 带宽”，需要 `htb`/`tbf`/`cake` 等 qdisc 与 class 配置；`prio` 适合演示优先级分类。

## 5. 参数说明

| 参数 | 默认 | 说明 |
|---|---|---|
| `--iface` | `lo` | 网卡名 |
| `--direction` | `egress` | `ingress` / `egress` |
| `--drop-port` | `6881,6882,6883` | 目的端口，最多 8 个 |
| `--video-port` | `1935,8080` | 目的端口，最多 8 个 |
| `--video-mark` | `16` | 写入 `skb->mark` 的值 |
| `--event-sample` | `64` | 丢包事件采样 |
| `--stats-interval` | `5` | 统计间隔 |

## 6. 验证

```bash
# 程序与链接
sudo bpftool prog show | grep -A5 tc_qos
sudo bpftool net show

# qdisc/filter
tc -s qdisc show dev lo
tc filter show dev lo egress

# map
sudo bpftool map show | grep -E 'tc_(config|stats|events)'
```

退出后：

```bash
sudo tc qdisc del dev lo clsact
sudo tc qdisc del dev lo root
```

> aya 的 `qdisc_add_clsact` 只负责 clsact；根 qdisc（`prio`）需要手动清理。

## 7. 生产化建议

1. **方向**：QoS 用 egress；入向防护用 ingress 或 XDP。
2. **qdisc 选型**：优先级用 `prio`；带宽保证用 `htb`；限速用 `tbf`/`police`；低延迟用 `fq_codel`/`cake`。
3. **分类依据**：生产上通常结合 DSCP、cgroup、uid、mark；本案例只用目的端口。
4. **避免误伤**：只匹配 TCP/UDP 且首片段；非 IP 放行。
5. **TCX vs clsact**：新内核（6.6+）aya 默认可能使用 TCX；TCX 与 clsact 的执行点相同，但 qdisc/mark 语义要以目标内核为准。需要经典 clsact 时可在代码中显式使用 `TcAttach::Netlink`（本项目默认 auto）。
6. **监控**：导出 `tc_stats`，同时采集 `tc -s qdisc` 的 backlog/drops；两者结合才能区分“BPF 丢包”和“qdisc 丢包”。
7. **性能**：`TcContext::load` 每头一次 helper 调用；若只按端口过滤，可考虑直接用 `load::<u16>` 读取目的端口，减少解析。当前实现为了可读性和 VLAN 支持保留完整解析。

## 8. 排错

| 现象 | 原因 | 处理 |
|---|---|---|
| `tc` 附加失败 | 没有 clsact / 权限不足 | 手动 `tc qdisc add dev X clsact`；用 root |
| 看不到丢包 | 方向/接口不对；loopback 路径不经过 | 换 veth/真实网卡；确认 `tc filter show` |
| mark 不生效 | 根 qdisc 不是 `prio`，或 `fw` 规则 handle 不匹配 | 检查 `tc filter show` 与 `--video-mark` |
| `tc qdisc del ... clsact` 报错 | qdisc 不存在 | 忽略或先 `tc qdisc show` |
| 统计有但事件少 | 采样率 | 调小 `--event-sample` |

## 10. 延伸

- 用 `bpf_skb_store_bytes` 改写 DSCP/ToS，再由交换机/上游 QoS 处理；
- 用 `bpf_redirect` 做流量重定向；
- 用 `tc_classid` + `cls_bpf` 做 classful qdisc 分类；
- 用 `htb` + `bpf` filter 实现按 cgroup/uid 的带宽分配；
- 用 `bpf_skb_ecn_set_ce` 做 ECN 标记。
